# Audit Artifact Spec

This contract is the source of truth for client-auditor disk state. Agents communicate through these files, not through conversational memory.

## Directory Layout

```text
audit/
  metadata.md
  manifest.md
  spawn_manifest.md
  progress/                       # per-phase progress; agents create their own (no pre-skeleton)
  findings/                       # AUTHORITY for every vulnerability claim
    _drafts/                      # hunt/xsub/depth write here (pre-promotion)
      {focus}-{NN}-{slug}.md
    {C|H|M|L|I}-{NNN}-{slug}.md   # canonical findings; PREFIX = current severity
    _false-positives/             # REFUTED findings, prefix becomes FP-
      FP-{NNN}-{slug}.md
  findings_inventory.md           # DERIVED VIEW (auto-generated by inventory; do not hand-edit)
  verification_queue.md           # orchestrator-owned work list for verify phase
  depth/{lens}.md                 # depth lens scratch outputs (promotions get copied to _drafts/)
  adversarial_review.md           # recommendations only; does not edit findings
  coverage.md
  report.md
```

See `finding-format.md` for the canonical finding file schema; every finding is one file in `findings/`. Verification fields live in that file's frontmatter and a `## Verification` body section, not in a separate artifact.

## Stage Ownership

| Stage | Owns | May Read | Must Not Write |
|-------|------|----------|----------------|
| Recon | `manifest.md`, `spawn_manifest.md`, `progress/recon.md` | source tree | findings, inventory, queue, depth, adversarial, report |
| Hunt | `findings/_drafts/{focus}-*.md`, `progress/hunt-{focus}.md` | assigned source files, assigned pattern/lens references | non-draft findings, inventory, queue, verify content of other findings, report |
| Cross-subsystem | `findings/_drafts/xsub-*.md`, `progress/xsub.md` | manifest, progress, scoped source files | same as hunt |
| Depth | `depth/{lens}.md`, `findings/_drafts/depth-{lens}-*.md`, `progress/depth-{lens}.md` | manifest, inventory view, scoped source files | non-draft findings, inventory, queue, report |
| Inventory | `findings/*.md` (promote / supersede / FP / severity mv), `findings_inventory.md`, `coverage.md`, `progress/inventory.md` | manifest, drafts, depth, all findings, previous inventory | verify-owned frontmatter blocks (`verification_*`), report |
| Verification (orchestrator side) | `verification_queue.md`, `progress/verification_queue.md` | inventory, findings | finding content |
| Verifier (per-finding) | one assigned finding file: `verification_*` frontmatter + `## Verification` body block, `progress/verify-{ID}.md` | the assigned finding, source files | other findings, queue, inventory, drafts, depth, adversarial, report |
| Adversarial | `adversarial_review.md`, `progress/adversarial.md` | inventory, findings, source files | findings (recommends changes only — inventory applies them on rerun), report |
| Report | `report.md`, `progress/report.md` | metadata, manifest, all findings, inventory view, queue, coverage, adversarial | findings (no editing), drafts, source files, tests |

## Observability Contract

Every phase has a progress artifact following `specs/progress-format.md`. **Agents create their own progress file as their first action** — the orchestrator does not pre-create skeletons.

- Agent's first file-write action before any source reading: write `audit/progress/{phase}-{owner}.md` with `Status: in-progress` and the required frontmatter.
- Agent must update the file at each checkpoint and before returning.
- If blocked, agent sets `Status: blocked` with a concrete blocker.
- The orchestrator may poll `audit/progress/` via `ls`, `find -newer`, or by reading the `Last Updated` field to detect stalled agents.
- If a phase is intentionally skipped, the orchestrator writes a progress file with `Status: skipped` and the reason in `Blockers:` — no agent needed.

## Completion Gates

Gates are run as inline Bash one-liners by the orchestrator at the end of each phase, defined in `SKILL.md`. Agents also run a self-check checklist before returning (see each agent's prompt).

Authoritative gate rules:

- `spawn_manifest.md` is required after recon; every `Required = YES` row must have a unique focus, 1-3 assigned entry-point clusters, and explicit output/progress paths.
- `progress/recon.md` must exist and be terminal (`complete` | `skipped` | `blocked`) by start of hunt.
- Every required hunt must reach `Status: complete` with `Entry Points Remaining: none` at the exact `Progress Output` path from `spawn_manifest.md`. Zero drafts under its `Expected Output Prefix` is **not** a gate failure when the progress file also records `Findings Touched: 0`. `Status: blocked` is terminal for observability but blocks Stage 3 completion until the orchestrator triages and re-runs that row.
- `progress/xsub.md` must exist by inventory time (skipped marker is acceptable).
- After inventory: `findings_inventory.md`, `coverage.md`, and `progress/inventory.md` must exist; every file in `findings/` must have a valid `id`, `status`, and `severity` in its frontmatter.
- Every active finding (`status` ∈ {active, verified}) with `verification_required: true` must be queued in `verification_queue.md` (default mode: `severity` ∈ {Critical, High, Medium} unless explicitly downgraded with `verification_required: false` + reason; deep mode: same plus depth-promoted findings).
- After verify: every queued `id` has `verification_status` set (not `unverified`) in its finding file's frontmatter.
- In deep mode, every triggered depth lens has `depth/{lens}.md` and `progress/depth-{lens}.md`; `progress/adversarial.md` exists.
- `report.md` may not be written before inventory and required verifications are complete. Report is formatting only.
- `progress/report.md` is required after report generation.

**Reverse rule (anti-pattern, hard rule)**: To make a gate pass, agents and orchestrator must never delete or move an already-written verifier artifact, finding file, or progress file. If a gate fails because an artifact is "extra" or "no longer required," the gate definition is wrong — fix the gate, not the artifact.

## Agent Scope Directive

Every non-report agent prompt must end with a scope directive naming exactly which files it may write. If an agent writes a later-stage artifact (e.g. hunt writing a canonical finding instead of a draft, or verifier editing `## Root Cause`), the orchestrator records the violation in `coverage.md` and either reverts the change or re-spawns a corrected agent.
