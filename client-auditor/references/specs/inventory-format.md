# Findings Inventory View

`findings_inventory.md` is a **derived view**, auto-generated by the inventory agent from the frontmatter of every file under `audit/findings/`. It is not authoritative. The authority for each finding is the per-finding file at `audit/findings/{PREFIX}-{NNN}-{slug}.md` (see `finding-format.md`).

Do not hand-edit `findings_inventory.md`. Edits will be overwritten on the next inventory run.

## Generation Rule

The inventory agent regenerates this file at the end of every inventory pass by scanning:
- `audit/findings/{C,H,M,L,I}-*.md`
- `audit/findings/_false-positives/FP-*.md`

It does **not** include `audit/findings/_drafts/`.

## Required Structure

```markdown
# Findings Inventory (derived view)

> Auto-generated from frontmatter of `audit/findings/*.md` by the inventory agent.
> Authority lives in the per-finding files. Do not hand-edit.
> Last generated: <ISO-8601>

## Summary
| Severity | Count |
|----------|-------|
| Critical | <N> |
| High | <N> |
| Medium | <N> |
| Low | <N> |
| Informational | <N> |
| Superseded | <N> |
| False Positive | <N> |

## Active Findings
| ID | Severity | Status | Title | Location | Verification | Reportable |
|----|----------|--------|-------|----------|--------------|------------|

## Superseded
| ID | Title | Superseded By |
|----|-------|---------------|

## False Positives
| ID | Title | Reason |
|----|-------|--------|
```

Field source:
- `ID`, `Severity`, `Status`, `Title`, `Reportable` — from finding frontmatter
- `Location` — from `location:` frontmatter (`file:line`)
- `Verification` — `<verification_status> <verification_evidence_tag>` from frontmatter
- `Superseded By` — from `superseded_by:` frontmatter
- FP `Reason` — from `verification_classification:` or last `severity_history` entry

## Severity Authority

Severity is set per-finding by inventory using `judging.md` rules. This view file does not authoritatively encode severity; the per-finding `severity` frontmatter does. Severity changes always:
1. Update the finding's `severity` field
2. Append a `severity_history` entry
3. `mv` the finding filename to the new `PREFIX-` prefix

This view file is regenerated to reflect the change automatically.

## Dedup Authority

See `finding-format.md` § Dedup Rules. Inventory never deletes a finding; merged duplicates become `status: superseded` with `superseded_by:` pointing to the canonical.

## Empty Inventory

If zero findings exist (no drafts promoted, no prior canonical findings), the view file MUST still be written with:
- the header block and `Last generated:` timestamp
- the Summary table with every row present and `<N>` replaced by `0`
- all three section headings (`## Active Findings`, `## Superseded`, `## False Positives`) and the table headers, with no data rows

An empty view file is a valid signal that inventory ran but produced no findings — downstream gates and the report agent must handle this case gracefully.
